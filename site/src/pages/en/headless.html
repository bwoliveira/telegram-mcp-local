Headless server

Run it on a Linux server you control

On an always-on computer, such as a mini PC or a homelab container, Unofficial Telegram MCP runs only from the command line: a user service syncs your chats and serves MCP clients on the same machine.

What the setup looks like

  • The telegram-mcp serve daemon runs as a systemd user service and restarts if it stops.
  • By default it listens only on 127.0.0.1:47831. MCP clients need the service token; the browser panel opens through a single-use link.
  • Without a desktop, secrets live in an encrypted file whose key is kept outside the data folder.
  • It starts read-only, just like the app.

Never expose the port

The panel and the MCP endpoint give access to your chats. Do not open the port to the internet, do not put a public proxy in front of it and do not point a domain at it.

To use it from another computer, go through an SSH tunnel or a private network of your own, such as Tailscale, always reaching the server's 127.0.0.1.

Step by step

  1. Install the binary

    The installer selects the architecture, checks the minisign signature and SHA-256, and installs the CLI in ~/.local/bin, without sudo. Use --prefix for a different folder. Add the folder to your PATH. It needs curl, tar and minisign.

    {{template "cmd" (cmd . "curl -fsSL https://raw.githubusercontent.com/bwoliveira/telegram-mcp-local/main/install.sh | sh")}} {{- if .Prelaunch}}

    Works only after launch: the repository is still private. For development, use authorized private artifacts.

    {{- end}}

  2. Enter your credentials and install the service

    In Bash, enter your api_id and api_hash from my.telegram.org/apps. These variables seed the encrypted vault on first launch; they are not saved in the service file.

    {{template "cmd" (cmd . "export TELEGRAM_MCP_SECRETS=file\nread -rp 'api_id: ' TELEGRAM_API_ID\nread -rsp 'api_hash: ' TELEGRAM_API_HASH; echo\nexport TELEGRAM_API_ID TELEGRAM_API_HASH\ntelegram-mcp service install --no-open\nunset TELEGRAM_API_ID TELEGRAM_API_HASH\ntelegram-mcp service status")}}

  3. Sign in

    Open the panel through the SSH tunnel below and scan the QR code with Telegram on your phone. Without a browser, use the prompts for your phone number, login code and two-step verification password:

    {{template "cmd" (cmd . "telegram-mcp auth --phone")}}

  4. Connect your AI client

    Print the settings for Claude Code and Claude Desktop:

    {{template "cmd" (cmd . "telegram-mcp config")}}

    Clients that speak MCP over stdio can use the bridge subcommand, which forwards calls to the daemon. For example, in Hermes Agent:

    {{template "cmd" (cmd . "hermes mcp add telegram --command \"$HOME/.local/bin/telegram-mcp\" --args bridge")}}

Reaching the server from another computer

On your computer, open the SSH tunnel:

{{template "cmd" (cmd . "ssh -N -L 47831:127.0.0.1:47831 user@server")}}

On the server, run this command, then open the printed URL in your computer’s browser:

{{template "cmd" (cmd . "telegram-mcp open --print")}}

Anyone with the URL can access the panel. It expires after one minute and can only be used once. Do not share or log it. MCP clients still need the token.

Maintenance

Service commands:

{{template "cmd" (cmd . "telegram-mcp service status\ntelegram-mcp service stop\ntelegram-mcp service start\ntelegram-mcp service uninstall")}}

Stopping or uninstalling the service does not sign you out or delete the history. The session stays listed in Settings › Devices on your phone until you end it.

What this mode does not do

There is no public endpoint, and no access from claude.ai on the web or from mobile apps. The server only serves clients that reach its 127.0.0.1, directly or through a tunnel.
