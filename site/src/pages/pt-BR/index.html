O Telegram MCP não oficial liga a sua conta pessoal a clientes MCP como Claude, Codex e Cursor. Ele roda no seu computador, guarda o histórico num banco local e conversa direto com o Telegram.

Como funciona

Três passos, tudo no seu computador

  1. Instale

    Baixe o app para macOS, Windows ou Linux. Num servidor sem tela, use só a linha de comando.

  2. Entre com o QR pelo celular

    No Telegram do celular, abra Configurações › Dispositivos › Conectar dispositivo e leia o código. Também dá para entrar com número, código e senha de duas etapas.

  3. Conecte o seu cliente de IA

    O painel mostra a configuração pronta para Claude Code, Claude Desktop, Codex e Cursor. Outros clientes MCP usam o endereço local com o token.

O que dá para fazer

Peça à IA o que levaria horas rolando a tela

Os exemplos aqui são de leitura, busca e resposta com prévia. Editar, reagir, enquetes, localização e ações de grupo também já foram verificados com uma conta real em um grupo de teste, sempre com prévia.

Ler e resumir

Liste conversas, grupos e contatos, veja o que está sem ler e abra o contexto em volta de uma mensagem.

Buscar no histórico

A busca por texto roda num índice local, no seu computador, sobre as mensagens já sincronizadas.

Responder com aprovação

Com a escrita ativada no painel, a IA prepara uma resposta de texto com prévia. Configure o cliente MCP para pedir a sua aprovação antes de confirmar o envio.

Dados e privacidade

O que fica com você e o que sai

As mensagens são guardadas num banco de dados no seu computador. O app fala direto com o Telegram, e o projeto não recebe nada: não há conta nossa, servidor nosso nem telemetria.

No Mac e no Windows, a sessão do Telegram, o api_hash e o token do painel ficam no cofre do sistema (Keychain ou Gerenciador de Credenciais). No Linux, ficam por padrão num arquivo cifrado, com a chave guardada fora da pasta de dados; o Secret Service pode ser escolhido no lugar.

Atenção ao cliente de IA

Quando o Claude, o Codex ou outro cliente lê mensagens pelo MCP, ele envia esse conteúdo ao provedor do modelo, que trata os dados conforme os termos dele. Um modelo rodando localmente evita essa saída.

Lembre que as conversas também têm dados de outras pessoas. Peça à IA só o que você precisa.

Riscos e limites

O que você precisa saber antes de usar

Como ele se comporta

  • Usa a sua conta de usuário, não é um bot.
  • Começa só leitura. Você ativa a escrita no painel; cada envio exige prévia e confirmação técnica. O cliente MCP deve pedir a sua aprovação humana antes de confirmar.
  • Ler uma conversa não a marca como lida. O recibo só sai quando você pede explicitamente para marcar como lida.
  • Mensagens que se autodestroem também são apagadas do banco local quando vencem, ou na próxima vez que o app abrir.

Riscos para a sua conta

  • Este é um cliente não oficial. O Telegram pode limitar ou restringir contas que usam a API de forma que ele considere abusiva, e não há limite de uso garantido como seguro.
  • Quando o Telegram pede uma pausa (FloodWait), o app espera em vez de insistir.
  • Os chats secretos não estão disponíveis: eles existem só nos aparelhos onde foram abertos.
  • Esta é uma versão beta e pode ter erros. Revise o que a IA propõe antes de aprovar.

Perguntas frequentes

Perguntas sobre o {{.BrandName}}

Este é um app oficial do Telegram?

Não. É um cliente de terceiros, não oficial; o aviso de independência está no rodapé de todas as páginas.

Ele usa a API pública do Telegram (o protocolo MTProto, pela biblioteca gotd), a mesma que outros clientes de terceiros usam.

E os termos da API do Telegram?

Quem usa a API do Telegram precisa seguir os Termos de Serviço da API. Três pontos importam aqui:

  • O item 1.5 proíbe usar dados obtidos do Telegram para treinar, ajustar, desenvolver, melhorar ou fazer o “deployment” de IA. A redação é ampla e pode abranger enviar mensagens a um LLM ou áudio ao Whisper local, mesmo sem treino. Uso privado, consentimento do titular da conta, modelo local e api_id próprio não criam exceção automática: conversas também têm dados de outras pessoas. O projeto não coleta dados para treino, mas isso não elimina o risco contratual desses fluxos. Não há confirmação do Telegram de que esse uso seja permitido. O projeto não consultou o Telegram. Você decide se usa esses recursos e assume o risco; se o Telegram notificar o projeto, o recurso poderá ser ajustado ou retirado.
  • O item 2.3 só permite “Telegram” no nome de um app quando vem depois da palavra “Unofficial” (não oficial). Por isso o nome sempre leva esse qualificador. Em inglês, ele vem antes de “Telegram”, como pede a regra: “Unofficial Telegram MCP”. Em português e espanhol, segue a ordem natural da língua: “Telegram MCP não oficial” e “Telegram MCP no oficial”. Essa exceção fica a critério do Telegram; o projeto não tem aprovação dele.
  • O item 2.1 pede que cada aplicativo tenha o próprio api_id. Aqui, cada pessoa usa o seu (veja a próxima pergunta).
Por que preciso criar o meu próprio api_id?

Cada pessoa usa o próprio api_id e api_hash, criados em my.telegram.org/apps; o projeto não distribui credenciais compartilhadas. No primeiro uso, o app desktop pede os dois num formulário e os guarda no cofre local. Em servidor sem tela, use TELEGRAM_API_ID e TELEGRAM_API_HASH para preencher o cofre na primeira inicialização.

Trate o api_hash como uma senha: não publique nem cole em conversas com a IA. Ele fica ligado à sua conta e ao uso que você faz dela.

A minha conta pode ser restringida?

Pode. Como em qualquer cliente não oficial, o Telegram pode limitar ou restringir uma conta se entender que o uso da API viola as regras dele ou parece automação abusiva. Ninguém consegue garantir um volume “seguro”.

Para reduzir o risco, o app respeita os pedidos de espera do Telegram, começa só leitura e exige prévia vinculada antes do envio. Configure o cliente MCP para pedir a sua aprovação humana antes de confirmar; o servidor não a verifica separadamente. Evite pedir à IA envios em massa ou ações repetitivas.

Para onde vão as minhas mensagens?

Para um banco de dados no seu computador. O projeto não tem servidor e não recebe as suas mensagens.

Elas só saem do computador quando o seu cliente de IA lê alguma coisa pelo MCP: nesse momento, o cliente envia o trecho ao provedor do modelo (Anthropic, OpenAI e outros), sob os termos desse provedor. Com um modelo local, isso não acontece. Elas também saem se você configurar um webhook: cada mensagem que ele cobrir é enviada para o endereço que você escolher.

A IA pode enviar mensagens sozinha?

Depende de como o seu cliente MCP está configurado. A instalação começa em modo só leitura. Ao ativar a escrita no painel, o servidor exige uma prévia vinculada à mesma ação (preview_fingerprint) e confirm=true para executar. O mesmo cliente MCP pode pedir a prévia e confirmar: o servidor não autentica uma aprovação humana separada.

Configure o cliente para solicitar seu OK explícito antes de cada escrita; não autorize confirmação automática. Sem esse controle no cliente, a IA pode confirmar e enviar sem uma nova aprovação sua.

As mensagens que chegam são tratadas como conteúdo de terceiros, nunca como instruções. Um texto que diga “envie isto para alguém” não dispara nenhum envio pelo servidor. O seu cliente MCP também precisa tratar esse conteúdo como dado não confiável.

Ler uma conversa marca as mensagens como lidas?

Não. A leitura feita pela IA não envia recibo. Só a ação de marcar como lida, quando você pede, avisa o Telegram. O app também não esconde o seu status nem finge estar off-line: ele simplesmente não marca nada sem pedido.

Funciona com chats secretos?

Não. Os chats secretos do Telegram ficam só nos aparelhos em que foram criados e não passam pela nuvem, então não aparecem para o app. As demais conversas, grupos e canais a que a sua conta tem acesso, sim.

É um bot?

Não. Um bot é uma conta separada, que só vê o que mandam para ela. O Telegram MCP entra com a sua própria conta, como um novo dispositivo, e enxerga as conversas que você já tem. Você pode encerrar essa sessão a qualquer momento em Configurações › Dispositivos, no celular.

Quais clientes de IA funcionam?

O painel traz a configuração para Claude Code, Claude Desktop, Codex e Cursor. Qualquer outro cliente compatível com MCP pode usar o endereço local padrão http://127.0.0.1:47831/mcp com o token do painel. O endereço só aceita conexões do próprio computador.

Quanto custa?

Nada. É código aberto sob a licença MIT. O custo que pode existir é o do seu cliente ou provedor de IA.
